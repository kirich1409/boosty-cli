# CI проверок

Срез добавляет автоматические проверки публичного репозитория. Локальный контракт уже задан в `AGENTS.md`: после изменений нужны `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`. Тесты не ходят в Boosty и не видят креденшелы разработчика. Провод API остаётся в `devapi.md` и `authorization_code_flow.md`. Этот файл его не копирует и не меняет. Примерные секреты, ключи и токены из контракта сюда не переносятся.

Закрытые решения из тела задачи и `AGENTS.md` не переоткрываются.

## Не входит

- Смена поведения CLI: команды, флаги, справка, коды выхода, человеческий текст, `--json`, auth, файл токенов, заголовки и разбор ответов.
- Новые endpoint, grant, поля и query.
- README и бейдж.
- `publish` остаётся `false`. Лицензия не добавляется.
- Pull request, push, тег и мерж. Вливание и push делает координирующая сессия после Done. Этот срез их не делает и GitHub Actions из этой задачи не запускает.
- Релиз, тег и выкладка бинарников.
- Секретные GitHub secrets.

## Публичный контракт команд

Контракт команд не меняется. Он остаётся тем, что уже записан в `AGENTS.md`: `auth login`, `auth refresh`, `auth status`, `user`, `subscription-levels`, `subscriptions`, `subscribers` и глобальный `--json`. Новой команды, флага, кода выхода и текста вывода нет.

## Workflow

Проверки живут в одном workflow-файле GitHub Actions в `.github/workflows/`. После среза это единственный workflow-файл в этом каталоге.

События, и только они:

- push в `main`
- pull request, база которого — `main`, включая обновление такого pull request

Фильтра по путям нет. Других событий нет.

На каждом таком событии из корня репозитория запускаются ровно три команды, как в `AGENTS.md`, и никакой другой вызов `cargo`:

- `cargo fmt --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo test`

Аргументы те же. `--offline`, `--locked`, `--workspace` и селектор пакета не добавляются: в этих командах их нет. Ненулевой код любой из трёх делает запуск неуспешным. Команда, чей код спрятан, проверкой не считается.

Три команды видны в самом workflow-файле. Скрипт вне файла, в котором они спрятаны, а в workflow их нет, эту проверку не закрывает.

Checkout репозитория и выбор toolchain нужны, чтобы команды запустились. Это не четвёртая проверка и не другой вызов `cargo`.

## Toolchain

Канал — stable. Его хватает, чтобы собрать текущий крейт edition 2024. Числовой релиз Rust не фиксируется. Заведомо старый toolchain, который edition 2024 не собирает, не выбирается. Edition крейта срез не понижает, чтобы сошёл старый Rust.

У выбранного stable есть rustfmt и clippy, иначе `cargo fmt` и `cargo clippy` не запускаются как эти команды.

## Окружение job

В окружении job нет `BOOSTY_API_KEY`, `BOOSTY_CLIENT_ID` и `BOOSTY_CLIENT_SECRET`. Workflow эти переменные не задаёт.

Файла токенов нет. Workflow его не создаёт, не кладёт в дерево job и не задаёт `BOOSTY_TOKEN_PATH`.

Секретные GitHub secrets не указываются. В workflow нет контекста `secrets`.

Тесты сами поднимают локальный сервер. Этого достаточно. Job не вызывает Boosty и не поднимает свой сервер вместо тестов.

## Что workflow не делает

Не публикует релиз, не создаёт и не пушит тег и не выкладывает бинарники. Артефакт job с бинарником — тоже выкладка. `cargo publish` нет: это был бы другой вызов `cargo`.

## Проверки

Проверка без запуска GitHub Actions — чтение workflow-файла в дереве:

- один workflow-файл GitHub Actions в `.github/workflows/`, и он там единственный
- события ровно push в `main` и pull request в `main`, включая обновление этого pull request, без фильтра путей и без других событий
- из корня репозитория видны ровно три команды `cargo` из `AGENTS.md`, с теми же аргументами; другого вызова `cargo` нет
- ненулевой код любой из трёх делает запуск неуспешным
- канал stable, без числового релиза Rust; rustfmt и clippy у этого toolchain есть
- нет `BOOSTY_API_KEY`, `BOOSTY_CLIENT_ID`, `BOOSTY_CLIENT_SECRET`, `BOOSTY_TOKEN_PATH`, файла токенов и контекста `secrets`
- нет релиза, тега и выкладки бинарника, включая артефакт job с бинарником
- job не вызывает Boosty и не подменяет локальный сервер тестов своим

Отдельным просмотром дерева срез не меняет поведение CLI, README, бейдж, `publish` и лицензию.

Локально, из корня репозитория, зелёные те же три команды:

- `cargo fmt --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo test`

`cargo test` по-прежнему не ходит в Boosty и не читает креденшелы разработчика.

Сам GitHub Actions из этой задачи не запускается. Зелёный прогон на GitHub недоступен, пока другая сессия не запушит. Его отсутствие не заменяет чтение workflow-файла и не считается провалом проверки, которую можно сделать здесь.
